# 发布与复盘
发布设置，以及用抖音创作者中心导出数据做复盘的方法和参考数值。

## 发布
- 时间：晚 20–21 点（情绪向内容在 22–23 点最热）；凌晨发布的首轮几乎没有流量。
- 标题：中文钩子并暗示有结局（如「17岁生日，我以为没人记得我…」），不要只写英文歌名和标签。
- 置顶评论放全文歌词（观众会自己手打歌词）和「回看第 X 秒」彩蛋提示；前几个小时多回评论，回复楼会把评论量带起来。

## 复盘方法
- 用户会上传 xlsx：流量（每小时播放）、内容吸引力（逐秒留存 + 同类作品）、观众参与度、观众、粉丝、全部评论。没有 python 和 unzip，用 node 加载 `node_modules/.pnpm/fflate@*/node_modules/fflate` 解压，再用正则读 sharedStrings 和 sheet XML。
- 算每秒流失率（这一秒走掉的人 ÷ 当时还在的人），除以同类作品同一秒的流失率得到倍数；再把镜头按内容归类（剧情推进 / 情绪蒙太奇 / 尾声）算平均倍数，找出哪类内容在掉人。
- 把流失归因到某个画面之前，先比较它之前、当时、之后各 2–3 秒的倍数：只有「当时或之后 1–2 秒」明显升高才算数。曾经把流失误判为黑场造成，实际上是紧接着重唱的副歌。
- 评论按主题计数，看反转有多少人讨论、有没有人看不懂。

## 评论要分清是对谁说的
- 什么时候用：复盘评论、设计开场文字时
- 依据：开场用第一人称写「今天是我17岁生日」，观众当成了作者本人的生日。约六成评论是对作者说的祝福（「陌生人生日快乐」「祝屏幕前的小鬼生日快乐」「等过生日我也这样发」），讨论剧情反转的只占约 5%。
- 做法：统计时把「对作者/人设说的」和「对剧情说的」分开。第一人称文字能带来对作者的互动，适合想经营人设的账号，但不能当成剧情被看懂的证据。
- 避免：把评论多归功于钩子写得好。
- 来源：work-bdd5c2f8（用户指出）

## 参考数值（work-bdd5c2f8，99 秒，首日）
- 播放 5.55 万；点赞率 7.11%、评论率 0.57%、分享率 1.25%、收藏率 2.59%、不感兴趣率 0.07%；完播率 4.16%、2s 跳出 32.9%、5s 留存 47%、平均看 15 秒。
- 结论：互动强、留存弱，两轮推荐后停在 5 万多，没进更大的流量池。评论约六成是观众以为作者过生日而发的祝福；讨论反转的只占约 5%。
