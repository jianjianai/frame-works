# 复盘数据
各作品发布后的数据记录和复盘方法；新作品发布后在这里追加一节，和已有数据对比。

## 复盘方法
- 数据：创作者中心导出的 xlsx（指标数据、播放量每小时趋势、留存分析逐秒留存 + 同类作品、流量来源、涨粉每小时趋势、全部评论）。读法看环境：有 python3 + openpyxl 就直接读（2026-10-10 复盘《mirrors》时可用；xlsx 放单独目录，用 `python3 -I` 跑脚本）；没有就用 node 加载 `node_modules/.pnpm/fflate@*/node_modules/fflate` 解压，再用正则读 sharedStrings 和 sheet XML。
- 导出的 xlsx 存进对应作品的 `public/uploads/<导出日期>/`，按内容改名：流量数据、内容吸引力数据、观众参与度数据、粉丝数据、流量来源、涨粉脱粉与不感兴趣（导出了全部评论就一起放）。作品发布后只读，要先取消发布，传完再发布。导出的 xlsx 没压缩，重新压缩一遍（内容不变）小 3 倍多。传完用 version_diff 看 index 行的 git blob 哈希，和本地 `git hash-object` 对一下；files_batch read 给的 sha256 是把文件当文本算的，二进制文件有些错查不出来。
- 逐秒流失率 = 这一秒走掉的人 ÷ 当时还在的人；除以同类作品同一秒的流失率得到倍数（低于 1 = 比同类留得住）。把镜头按内容归类（剧情推进 / 情绪蒙太奇 / 尾声）算平均倍数，看哪类内容在掉人。
- 段落倍数 = 这一段从头到尾走掉的比例 ÷ 同类同一段走掉的比例。先把每一秒的画面（作品时间轴 EV）和歌词（krc 逐字时间）列出来，再按镜头、按幕各算一遍。
- 把流失归到某个画面前，先比较它之前、当时、之后各 2–3 秒的倍数，只有当时或之后 1–2 秒明显升高才算。曾把流失误判为黑场造成，实际是紧接着重新唱起的副歌。
- 估算改动的收益：假设某一段按同类的流失率走，算结尾还剩多少（《mirrors》47–57 秒按同类走，看完的人从 13.0% 变成 15.2%，多 17%）。
- 平台的「完播率」和留存曲线最后一秒不是一个口径（《mirrors》26.61% 对 13.0%，《unhappy》16.93% 对 3.19%，差 2–5 倍不等）；和同类、和别的作品比留存都用留存曲线。
- 流量来源表是这一支自己的；「对比7日」= 这一支 − 账号近 7 天的平均（三次导出都算出推荐页平均约 92.2%、个人主页约 4.4–4.5%；《unhappy》这次还算出消息页约 1.8%、搜索约 1.0%）。
- 每小时播放加起来和指标数据的播放量对不上（重置版 12.26 万对 12.03 万）：总数用指标数据，每小时只看形状。
- 用同一首歌的作品按歌曲时间对齐，比较同一句歌词处的倍数，能把歌的影响和画面的影响分开（原版和重置版在 18–20 秒同一句歌都是全片最高，画面完全不同）。
- 评论按主题计数，分开「对作者说的」和「对剧情说的」。
- 流量要等第二波：《mirrors》第二天白天几乎停了，晚上的第二波比第一天还大。发布 3 天、7 天后最好再导出一次。
